[0]  TECH STACK & ARCHITECTURE
================================================================================

LANGUAGE:
  - Kotlin (100%)

UI FRAMEWORK:
  - Jetpack Compose (Material 3)
  - Navigation: Jetpack Navigation Compose
  - State: ViewModel + StateFlow + Compose State

DATABASE:
  - Room (SQLite wrapper)
  - No external backend for Phase 1–12 (fully offline)

DEPENDENCY INJECTION:
  - Hilt (Dagger Hilt for Android)

CONCURRENCY:
  - Kotlin Coroutines + Flow

ON-DEVICE AI (Phase 5+):
  - Google MediaPipe LLM Inference API (Gemma-2B)
  - OR: Rule-based IMCI decision engine as fallback

IMAGE/MEDIA:
  - Coil (image loading)
  - ZXing / ML Kit (QR code generation & scanning)

SECURITY:
  - Android Keystore (encrypted PIN storage)
  - SQLCipher (optional: encrypted Room DB)

NOTIFICATIONS:
  - WorkManager (background tasks, follow-up reminders)
  - AlarmManager (vaccine due date alerts)

FUTURE (Phase 13):
  - Retrofit + OkHttp (Django REST API sync)
  - DataStore Preferences (sync metadata)

ARCHITECTURE PATTERN:
  - MVVM (Model - ViewModel - View)
  - Repository Pattern (ViewModel → Repository → Room DAO)
  - Clean Architecture layers:
      UI Layer      → Composables, ViewModels
      Domain Layer  → Use Cases, Business Logic
      Data Layer    → Repositories, DAOs, Room Entities

------------------------------------------------------------------------
1.4  UI DESIGN PRINCIPLES
------------------------------------------------------------------------
  - MINIMALIST: Reduce clutter. One task per screen section.
  - CARD-BASED: Use elevated Surface cards for grouping related content.
  - ICON + LABEL: Every action must have both icon and text label.
  - COLOR SEMANTICS: Red=urgent/danger, Yellow=caution/follow-up, Green=safe/ok
  - BOTTOM NAVIGATION: 4 tabs — Home, Triage, Library, Records
  - FLOATING ACTION BUTTON: Primary action on each screen (e.g., + New Patient)
  - LOADING STATES: Always show skeleton loaders, never blank screens
  - EMPTY STATES: Friendly illustration + message when no data
  - ERROR STATES: Clear error messages with retry option
  - ACCESSIBILITY: Min touch target 48.dp, adequate contrast ratios

[5]  PHASE 2 — IMCI TRIAGE ENGINE
================================================================================
  STATUS: ⏳ PENDING (After Phase 1)
  PRIORITY: 🔴 CORE

------------------------------------------------------------------------
5.1  OVERVIEW
------------------------------------------------------------------------
  The IMCI Triage Engine is the clinical brain of AfyaGPT. It guides
  CHWs through the WHO 4-step IMCI assessment protocol via:
    MODE A: AI Chat (Gemma-2B on-device) → conversational triage
    MODE B: Structured Forms (checkbox-based, no AI dependency)
  
  Both modes produce the same output: classification + treatment plan.

------------------------------------------------------------------------
5.2  TRIAGE START FLOW
------------------------------------------------------------------------
  Entry: Tap "Start Triage" from Home or Triage tab
  
  STEP 0 — Patient Selection
    - Search existing patient by name or ID
    - OR: "Register New Patient" → PatientRegistrationScreen (mini)
    - Display: Patient card (name, age, sex)
    - "Begin Assessment" button

  STEP 1 — General Danger Signs (ALWAYS FIRST)
    Screen: DangerSignsScreen
    Display: 4 large checkbox cards with icon + description:
      ✗ Unable to drink or breastfeed
      ✗ Vomiting everything
      ✗ Convulsions (current or history)
      ✗ Lethargic or unconscious
    
    If ANY checked → Red banner "DANGER SIGN DETECTED"
      → Show: Immediate Referral Instructions card
      → Button: "Create Emergency Referral"
      → Still allow proceeding to full assessment

  STEP 2 — Vital Signs Entry
    Screen: VitalsScreen
    Fields:
      - Weight (kg) — numeric input with visual weight scale
      - Temperature (°C) — with hot/cold indicator
      - Respiratory Rate — [built-in timer button] (see 5.3)
      - MUAC (mm) — with color band indicator: <115 RED, 115-125 YELLOW, >125 GREEN
    
  STEP 3A — Cough / Breathing Assessment
    Screen: CoughAssessmentScreen
    Fields:
      - Has cough or difficulty breathing? (Yes/No toggle)
      - [If Yes] Respiratory Rate result (from timer)
      - Chest indrawing? (Yes/No)
      - Stridor when calm? (Yes/No)
    Result → IMCIClassifier.classifyRespiratory()
      → SEVERE PNEUMONIA (Pink) / PNEUMONIA (Yellow) / NO PNEUMONIA (Green)
    Show: Classification chip + Treatment card (amoxicillin dosage)

  STEP 3B — Diarrhea Assessment
    Screen: DiarrheaAssessmentScreen
    Fields:
      - Has diarrhea? (Yes/No)
      - [If Yes] Days with diarrhea (number input)
      - Blood in stool? (Yes/No)
      - Sunken eyes? (Yes/No)
      - Skin turgor (Skin pinch test): Normal / Goes back slowly / Very slowly
      - Drinking ability: Drinks eagerly / Drinks poorly / Cannot drink
    Result → IMCIClassifier.classifyDiarrhea()
      → SEVERE DEHYDRATION (Pink) / SOME DEHYDRATION (Yellow) / NO DEHYDRATION (Green)
      → PERSISTENT DIARRHEA (if ≥ 14 days)
      → DYSENTERY (if blood in stool)
    Show: ORS/Zinc dosage calculator based on weight

  STEP 3C — Fever Assessment
    Screen: FeverAssessmentScreen
    Fields:
      - Fever currently or in last 7 days? (Yes/No)
      - Temperature °C (pre-filled from vitals)
      - Stiff neck? (Yes/No)
      - Malaria RDT result: Positive / Negative / Not Done
      - Measles rash? (Yes/No)
      - Days with fever: number input
    Result → IMCIClassifier.classifyFever()
      → MALARIA (Yellow) / SEVERE FEBRILE DISEASE (Pink) / FEVER NO MALARIA (Yellow/Green)
    Show: ACT dosage calculator if malaria positive

  STEP 3D — Ear Problem Assessment
    Screen: EarAssessmentScreen
    Fields:
      - Ear pain? (Yes/No)
      - Ear discharge? (Yes/No)
      - [If Yes] Discharge duration (days)
      - Mastoid tenderness? (Yes/No)
    Result → IMCIClassifier.classifyEar()
      → MASTOIDITIS (Pink) / ACUTE EAR INFECTION (Yellow) / CHRONIC EAR INFECTION (Yellow) / NO EAR PROBLEM (Green)

  STEP 4 — Nutrition Assessment
    Screen: NutritionAssessmentScreen
    Fields:
      - Visible severe wasting? (Yes/No)
      - Oedema of both feet? (Yes/No)
      - MUAC result (pre-filled from vitals)
      - Palm pallor: Severe / Mild / None
    Result → IMCIClassifier.classifyNutrition()
      → SAM (Pink) / MAM (Yellow) / NOT MALNOURISHED (Green)
      → SEVERE ANEMIA (Pink) / SOME ANEMIA (Yellow) / NO ANEMIA (Green)

  STEP 5 — Immunization Review
    Screen: ImmunizationReviewScreen
    - Load child's vaccination record
    - Show overdue vaccines in red
    - Allow marking given vaccines
    - Vitamin A: show if due

  STEP 6 — Triage Result Summary
    Screen: TriageResultScreen
    - Overall Risk Level banner (Critical/High/Medium/Low)
    - Classification cards per domain (Respiratory, Diarrhea, Fever, Nutrition)
    - Treatment Plan section:
        - Each medicine: name, dose, frequency, days, instructions
        - Dosage is auto-calculated from weight
    - Counseling Messages section (caregiver advice)
    - Actions:
        - "Create Referral" (if Pink classifications)
        - "Record Treatment" → saves treatment to DB
        - "Schedule Follow-up" → date picker
        - "Print/Share QR Summary"

5.5  DOSAGE CALCULATOR ENGINE
------------------------------------------------------------------------
  File: util/DosageCalculator.kt

  Amoxicillin (Pneumonia):
    Weight 4–6 kg    : 125mg twice daily × 5 days
    Weight 6–10 kg   : 250mg twice daily × 5 days
    Weight 10–19 kg  : 500mg twice daily × 5 days

  Artemether-Lumefantrine (Malaria — 20mg/120mg tabs):
    Weight 5–14 kg   : 1 tablet per dose (6 doses over 3 days)
    Weight 15–24 kg  : 2 tablets per dose
    Weight 25–34 kg  : 3 tablets per dose
    Weight ≥ 35 kg   : 4 tablets per dose
    Schedule: 0h, 8h, 24h, 36h, 48h, 60h

  ORS (Dehydration):
    Plan A: 50–100ml after each stool (home)
    Plan B: 75ml/kg over 4 hours (supervised)
    Plan C: IV fluids — refer immediately

  Zinc:
    Age < 6 months   : 10mg/day × 14 days
    Age ≥ 6 months   : 20mg/day × 14 days

  Paracetamol (Fever):
    10–15 mg/kg per dose, max 4 doses/day

5.6  AI CHAT MODE (Gemma-2B Integration)
------------------------------------------------------------------------
  Library: Google MediaPipe LLM Inference API
  Model: Gemma-2B (4-bit quantized, ~1.3GB)
  Download: First launch or from Settings → Download AI Model

  Chat Architecture:
    - System prompt embeds IMCI protocol as context
    - AI receives structured patient info as context
    - AI guides CHW through conversation
    - CHW responses parsed → structured data → IMCIClassifier
    - AI response always validated against IMCI rules

  Fallback: If AI model not downloaded → auto-switch to Form Mode

[18] GENERAL DEV RULES & CONVENTIONS
================================================================================

  NAMING:
    - Screens: [Name]Screen.kt
    - ViewModels: [Name]ViewModel.kt
    - Entities: [Name]Entity.kt
    - DAOs: [Name]Dao.kt
    - Repositories: [Name]Repository.kt
    - Use Cases: [Verb][Noun]UseCase.kt

  CODE STYLE:
    - Follow Kotlin official coding conventions
    - Max 80 characters per line where possible
    - All @Composable functions documented with KDoc
    - No business logic in Composables — always in ViewModel or UseCase
    - All hardcoded strings → strings.xml (for future multi-language)
    - All dimensions → use spacing constants (not magic numbers)

  GIT WORKFLOW:
    - Branch per feature: feature/auth-signup, feature/imci-triage, etc.
    - Commit messages: "feat:", "fix:", "refactor:", "test:", "docs:"
    - PR review before merging to main

  SECURITY:
    - Never log patient data
    - Never store raw PIN
    - Use Android Keystore for sensitive key storage
    - Validate all user inputs before DB operations
    - Use parameterized queries only (Room prevents SQL injection)

  PERFORMANCE:
    - LazyColumn for all lists (never Column with forEach)
    - ViewModel state as StateFlow, not LiveData
    - Use remember { } and derivedStateOf for derived state
    - Use Paging 3 for large patient lists (Phase 3+)
    - Preload medical library into Room at first launch (via DatabaseInitializer)

  ACCESSIBILITY:
    - All icons must have contentDescription
    - All interactive elements: min 48dp touch target
    - Support large font scale (no hardcoded sp with clipToOutline)
    - Color should not be the only differentiator (add icons/labels)
